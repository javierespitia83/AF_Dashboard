# IMPLEMENTATION.md — how the dashboard is built

Audience: an AI coding agent (or a developer) that must **recreate or change this app from the documents**. `SPEC.md` says *what* to build, `DATA_CONTRACT.md` says *what the data means*, `ACCEPTANCE.md` says *how to know it is done*, `DECISIONS.md` says *why*. This file says *how the code is organised*, so a rebuild lands on the same structure and the same behaviour. It follows SPEC and DATA_CONTRACT (precedence rule at the top of `SPEC.md`); the current code in this folder is the reference implementation. Appendix A is the step-by-step build plan and Appendix B the prompt for handing a rebuild to another agent (they replace the former `BUILD_PLAN.md` and `REBUILD_PROMPT.md`).

## 1. Stack and hard limits

- Static HTML, CSS and vanilla JavaScript (ES5-style in the app: `var`, `function`, no modules, no classes, no build). Served with `python3 -m http.server` from this folder. `file://` is unsupported (browsers block `fetch` of local JSON).
- No npm, no CDN, no web fonts, no library, no remote network calls. `dashboard.js` has one fetch path for relative local JSON: the sprint page loads `sprints.json`, then one selected snapshot `snapshots/sprint-<id>.json` (no fallback: a missing or invalid manifest shows an error), the backlog page loads `backlog.json`, and Quality Intake loads `quality-intake.json`. Charts are inline SVG built with `createElementNS`; bars and heat grids are HTML/CSS.
- **No `innerHTML`, `outerHTML`, `eval`, `new Function`, `document.write`, string `style` attributes.** Every DOM node is built with `AF.el` (text nodes only) so data can never inject markup. `AF.el` takes `style` only as an object of CSSOM properties and `on<event>` only as functions; it throws otherwise. The acceptance script greps for these.
- **Content-Security-Policy** (D79), identical in the three HTML files: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`. No inline script, inline style attribute or string handler may be added.
- Light mode only. System fonts only (`--font` stack in `dashboard.css`).
- The app is read-only: it writes nothing (not Excel, Jira or the JSON).

## 3. Page lifecycle

1. `AF.loadJson(file)` → the single `fetch(file, {cache:'no-store'})` path for relative local JSON. `AF.loadSnapshot(file)` calls it and requires `data.tickets` to be an array.
2. Sprint page: `loadManifest()` loads `sprints.json`, validates it (`validManifest`: exactly one active entry equal to `current`, unique positive integer ids, valid `YYYY-MM-DD` dates with `end >= start`, `state` active/closed, `file` matching `^snapshots/sprint-\d+\.json$`, optional string `note`; **unknown keys are ignored**, D74), builds the selector and picks `?sprint=<id>` or `current`. An unknown id shows "Sprint not found" with the selector usable. A missing/invalid manifest calls `AF.showError(app, 'sprints.json', err)`.
3. `loadSprint(entry)` increments a sequence number, tears down the previous view's ResizeObserver and Escape handler, shows "Loading sprint…", and reuses or starts the cached snapshot promise (cache per `entry.file`; a failed load is evicted). The snapshot must have `sprint.id/startDate/endDate` equal to the entry, otherwise the promise rejects with an `Error` whose `userMessage` says so (shown by `AF.showError`). When the promise settles, a response for an older selection is ignored (C2).
4. Load errors and drawing errors are separate: `.then(function (data) { try { init(data) } catch (err) { AF.showRenderError(app, err) } }, function (err) { AF.showError(app, file, err) })`. The same pattern is used on all three pages, so a bug in rendering never shows as "Can’t load …".
5. `init(data, entry)`: set the header timestamp, show the closed-sprint banner if applicable, clear `#app` and the filter bar, handle an empty ticket list (`AF.emptyMessage`, return), create a fresh store, build the shell and controls, subscribe, call `render()`. A sprint switch calls `init` again, so all filters reset.
6. `render()` is the only way the screen changes for regular filters: `f = store.apply(tickets)` then, in order, KPIs, burndown, status, type, Team Contribution, KPI-tile sync, the lower section (detail + matrix), `updateBar()` and select sync. When only the KPI (extra) filter changes the store emits reason `'extra'` and the page redraws just the lower section and the filter bar (same behaviour as before C10). Tiles are **redrawn from scratch** (they are small); there is no incremental DOM diffing.

Quality Intake: load and validate `quality-intake.json` (`sprints` must be an array), set the export timestamp, render one card per sprint, expand/collapse source ticket lists from button clicks (the card re-renders and focus returns to the clicked count). Only exact Jira URLs equal to `AF.jira.url(key)` are linked.

## 5. Page scripts

### sprint.js
- Seven dimensions: `status` (get → bucket label), `type` (exact issue type or `—`), `assignee` (`personName(owner)`), `tester` (`personName(tester)`), `contributor` (Team member: `matches` selected names against owner OR tester), `fix` (`fixVersion` or `(none)`), `parent` (`parent` or `(none)`).

Only the detail table and the matrix apply it (`{withExtra:true}`); KPI hints use `store.isActive({extra:false})`. Clickable KPI tiles are `section.kpi.clickable` with `role=button`, `tabindex=0`, `aria-pressed`; Carried over is clickable only when `sprint.carriedOver.ticketKeys` exists; non-clickable KPIs carry none of these attributes.
- Shell: `.kpis.k8` (eight `AF.kpi()` tiles, in order: Work items, Story points, Done, Added mid-sprint, Carried over, No tester & Not Dev to Test, Long-running work · 7+ days, Avg cycle time), `.main.sprint` (Burndown, Tickets by status, Tickets by type, Team Contribution), `.lower` (Ticket detail, Assignee x tester).

KPIs, burndown and detail use the fully filtered set `f`; status and type each exclude their own dimension, Team Contribution excludes Assignee, Tester and Team member, and the matrix excludes both of its dimensions.
- Status tile always shows rows for buckets 0–3, plus `Other` only if some ticket is in it; status rows always toggle (D60). Type rows sort by W.I desc, then name.
- Team Contribution keeps a CSS grid (`.colhead.contribution-grid`, `.contribution-row`, pinned `.tile-foot .contribution-grid.totalrow`) rather than a `<table>`, so the header and Total line stay outside the scrolling body; instead every `.contribution-name` / `.contribution-value` button has an `aria-label` such as "Ann Lee, Assignee W.I: 3. Filter Assignee" (D78). `data-key` values: `contributor:<name>`, `assignee:<name>`, `tester:<name>`.

- Key listings for focus restore: `data-key` values are `status:<name>`, `type:<name>`, `<dim>:<name>` and heat cells `<row>|<col>`.
- At the end: `AF.store = store; AF.tickets = tickets;` for console and test access.

## 7. Burndown (inline SVG)

**Model** — `AF.burndown(tickets, sprint, today, thr, removed, opts)`; returns `null` when `sprint` is missing or its dates are invalid (`end < start`; the sprint page never hits this because the manifest check guarantees the dates). For a closed sprint, `opts.closed` makes the effective chart date the sprint end and hides the live Today marker:
- `n` = calendar days from `startDate` to `endDate` inclusive (weekends included); `scope(i)` = story points of filtered tickets with `addDay ≤ i` (D45; `addDay` from `addedDate`, null/invalid/before start → 0, after end → last day); `total` = the largest scope on any day (y-axis top, including when removals lower the final scope).
- For each Done ticket: if `doneDate` is not a date → counted in `unplacedDone` (and not subtracted); else `idx = max(0, doneDay − startDay)` (a pre-start date counts on day 1); `idx ≥ n` → `afterEndDone` (ignored); otherwise add its points to day `max(idx, addDay)` (never before it entered the scope).
- `todayIndex = clamp(dayNum(today) − start, −1, n−1)`, `todayInside` = today within `[start,end]`. `today` is the snapshot's `refreshedAt`, **not the browser clock**.
- `days[i] = {date, scope, ideal: scope(0)·(1 − i/(n−1)), remaining: i ≤ todayIndex ? scope(i) − cumulativeDone : null, doneToday, doneTickets}` (the ideal starts at the *starting* scope).
- Removals (D52): `removed` = `sprint.removed` after `store.apply` (empty array when absent). Each entry with a valid `removedDate` adds its points at `addDay` and subtracts them at `removeDay`; `removedByDate[date]` feeds the markers.
- `mid = midSprintAdded(...)`; `addedByDate[date]` (every date after the start day) and `midByDate` (dates after `startDate + thr`) = lists of `{ticket, points, summary, status, owner}` grouped by `addedDate` (a date after the sprint end is clamped to the last day; a value that is not a date gets no marker). `thresholdDate = isoOf(start + thr)`.

**Drawing** — `AF.drawBurndown(container, model, opts)`; `opts = {thresholdDays, label, selectedKey, onMarker(kind, date, list)}` where `selectedKey` is `'added:YYYY-MM-DD'` or `'removed:YYYY-MM-DD'` and `kind` is `'added'` or `'removed'`:
- Geometry constants `CHART` (`minWidth 280`, `minHeight 120`, margins `left 42`, `right 16`, `top 42` / `topSmall 34` / `topTwoRowLegend 51`, `bottom 50` / `bottomSmall 36`, `removedExtra 18`, `smallHeight 260`, `narrowWidth 700` / `narrowWidthWithRemoved 760`, `labelSpacing 36`, `markerHalfWidth 14`) and `LEGEND` (row y positions, swatch 18, text gap 5, triangle 12, item offsets `oneRow {remaining 0, ideal 90, scope 160, added 230, earlier 410, removed 480}`, `twoRows {added 0, earlier 140, removed 210}`, reserved width 550 with removals / 470 without). The chart is sized to the container (`W = max(280, clientWidth)`, `H = max(120, clientHeight)`); narrow charts drop the y-axis title and start the legend at the left; when narrow and removal markers exist, the three marker legend items move to a second row and the plot starts at 51px. Y axis from 0 to `niceScale(total)`.
- Draw order (back to front): y grid + labels, per-day transparent hover rects (`rect.bd-day` with `data-date/remaining/ideal/scope/done` and `<title>` tooltips), x ticks and `M/D` labels (≥ 36px apart, last day always labelled), scope step line (`polyline.bd-scope`), ideal polyline (`polyline.bd-ideal`, dashed), Today marker (only if `todayInside`), remaining polyline (`polyline.bd-actual`, navy, dots, bigger last dot), markers, legend. After the SVG, a visually hidden `div.bd-data` holds a table (Date, Scope, Remaining, Ideal, Done that day) with the same per-day values for screen readers.
- Marker = `g.bd-added` (`data-date/count/points/early`; filled amber after the threshold, hollow white within it) or `g.bd-removed` (red triangle below the axis), each `tabindex=0`, `role=button`, `aria-pressed`, `aria-label`, containing a transparent `rect.bd-hit`, a triangle `path`, a `+N` / `−N` label and a `<title>` tooltip. The selected marker gets `is-selected`. Click, Enter or Space calls `opts.onMarker`.
- The page redraws the chart from a `ResizeObserver` on the tile body whenever its width or height changes; the observer object is kept and disconnected on every sprint switch (C2). Chart height comes from the container, never a fixed number (a fixed minimum cut the chart off at 1366×768).

**Marker panel** (`sprint.js`) — `selectedKey` and `pop` live in the page script. `onMarker(kind, date, list)` toggles: same key → close; other key → `showPanel(list)`; then redraw (so `is-selected`/`aria-pressed` update) and refocus the marker. `showPanel` appends `div.bd-pop[role=region][aria-label="Tickets added Sep. 26, 2026"]` to the tile root (non-modal: focus stays on the marker; header "Added Sep. 26, 2026" or "Removed …" via `AF.longDate`, "N tickets, P points", `.bd-pop-x` button; body: table Ticket (Jira link) / Summary / Pts / Status / Assignee). `renderBurndown` removes the panel at every render and re-shows it only if the selected date still has tickets in the new model; Escape (document-level `keydown`) closes it. It changes no filter.

## 8. Accessibility and interaction contract

Clickable things are real `<button>`s in tab order with a visible focus outline (`:focus-visible`, teal 2px; markers draw the ring on their hit area); selected state is `aria-pressed`; Enter/Space activates, and Ctrl/Cmd/Shift with Enter/Space multi-selects (the click event carries the modifier). Colour is never the only signal (names and numbers always shown). Text contrast is at least 4.5:1 everywhere, including dimmed items, heat cells and the LIVE button, and no text is below 10px (D78). Scroll boxes are focusable, labelled regions only while they scroll. Each page has one `h1`; every `th` has `scope`. Reduced motion is respected (no animations exist). Scroll position and keyboard focus survive a redraw (`AF.rebuild`).

## 9. Data pipeline (outside this folder, needed to refresh data)

`$AF_SNAPLOGIC_ROOT/03_Tracker/daily_tracker.xlsx` (moved from `03_Team_Enablement/` on 2026-10-29; `Daily`, `Backlog Prioritized`, `Sprint Metrics`, `Quality Intake Detail`) → `$AF_SNAPLOGIC_ROOT/05_Automation/export_dashboard_snapshots.py` (read-only, manual, atomic writes, refuses to run while the Excel lock file exists, needs `openpyxl`) → the active sprint snapshot, `backlog.json` and `quality-intake.json`. Sprint snapshots and the backlog use `schema/snapshot.schema.json` (the exporter checks only its top-level `required` and `tickets.items.required`); Quality Intake uses `schema/quality-intake.schema.json`. `--quality-intake-only` writes only the intake file. Mapping rules: `DATA_CONTRACT.md` and the skill `$AF_SNAPLOGIC_ROOT/06_Skills/af-dashboard-snapshot-export.md`. A rebuild with no tracker can use hand-made JSON. If a new field is needed, update the exporter, its skill, the relevant schema, fixture when applicable, and `DATA_CONTRACT.md` together.

Known data limits that the UI must keep showing, not hide: older snapshots may contain `addedDate` values from before the approximation marker was retired, but the marker is not preserved in JSON; removals are reflected only when `sprint.removed` is present, and re-estimates are not reflected; `sprint.carriedOver` has a ticket percentage only (no points percentage).

## 10. The acceptance harness (`scripts/run_acceptance.js`, `scripts/lib/`)

Design to copy if you rebuild it (D82):
- **Modules.** `lib/cdp.js` launches headless Chrome with a fresh profile and drives tabs over the DevTools protocol (every call has a timeout, `ACCEPT_CDP_TIMEOUT_MS`, default 30 s). `lib/files.js` stages copies, starts one `python3 -m http.server` per copy on a free port and waits until it answers, fingerprints the repository and finds the tracker. `lib/schema.js` is the one JSON Schema validator (type, enum, const, format date/date-time, pattern, min/max length, minimum/maximum, items, min/max items, uniqueItems, contains/minContains/maxContains, properties, required, additionalProperties, anyOf, allOf, local `$ref` into `$defs`/`definitions`); `unsupportedKeywords()` fails the run if a schema starts using anything else. `lib/model.js` is the **independent** expected-value model, computed in Node from the JSON and never from the app's own functions (the duplication of a few rules is intentional). `lib/page.js` holds the in-page snippets (`H` helpers such as `tile()`, `rowsOf()`, `clickRow()`, `clickCell()`, `setSel()`, `setQ()`, `readCommon()`, `colCells()`, `matrixOf()`, `paintedBg()`; readers `READ_BD`, `READ_SPRINT`, `READ_BACKLOG`, `READ_EPIC`, `LAYOUT`, `SCROLL_REGIONS`). `lib/ui_text.js` holds every UI string the checks expect. The per-page suites stay in `run_acceptance.js`; splitting them into separate `node --test` files was left for later.
- **What it serves.** A staged copy of only the app and data files (never the repository, so `.env`, `.git/` and the docs are not on a local port), plus throwaway variants with swapped data: missing, invalid, empty, fixture, links with odd data, a hand-made sprint with hand-computed answers, `carriedOver` null/zero/partial, `sprint.removed`, no/invalid manifest, a manifest with unknown keys, a manifest pointing outside `snapshots/`, a snapshot that does not match its entry, and data that makes every page's drawing code throw.
- **What it checks.** After **every** interaction it re-reads the screen and compares KPIs, tags, every tile, the table and the burndown (including its hidden data table) with the model. Test targets (assignees, testers, epics, priorities, matrix cells, the closed sprint) are derived from the loaded JSON. It also checks layouts at 1920×1080, 1536×864, 1440×900, 1366×768 (no page scroll) and 1280×720, 1024×768, 800×900, 480×900 (fallback), keyboard behaviour, contrast (computed in the page from painted colours), scroll regions, console cleanliness, only-localhost requests, the sprint-switch race and observer cleanup, source greps (no `innerHTML`/`eval`/inline style strings/CDN), the CSP meta, schema conformance of every manifest snapshot and its match with the entry, and Jira links. It runs `node --test scripts/unit.test.js` as one check.
- **Read-only proof.** A SHA-256 of every file under the repository (except `.git/`; `.env*` by size and time only) before and after; the tracker (found via `AF_TRACKER_PATH`, `AF_SNAPLOGIC_TRACKER`, then `03_Tracker/` and the former `03_Team_Enablement/` under `$AF_SNAPLOGIC_ROOT` or the usual Google Drive folder) by size and modification time, or SKIP when absent.
- **Exit codes.** 0 = all pass, 1 = a check failed, 2 = harness error. Results (`acceptance_results.json`) and screenshots stay in the scratch folder unless the run is clean.
- It depends on the DOM class names and `data-*` attributes listed in §5–§7; if you rename them, update `lib/page.js` in the same pass.

**Pitfalls found while building (do not repeat):**
- A tile helper that skipped the subtitle element when `sub` was an empty string crashed the page; create the element whenever `sub !== undefined`.
- Separate load errors from render errors (`.then(ok, onLoadError)` with a `try/catch` around rendering), or a render bug looks like "can't load file".
- Redrawing a tile loses keyboard focus and scroll: use `AF.rebuild` with `data-key`.
- CSS order: base rules before the media block, or the dashboard grid is overridden.
- Chart: never use a fixed minimum height; derive `H` from the container and use tighter margins below 260px; drop the axis title on narrow charts; do not draw "Today" when the snapshot date is outside the sprint.
- `ResizeObserver.observe()` returns `undefined`: keep the observer in its own variable or it can never be disconnected.
- A slow snapshot response must not overwrite a later sprint choice: compare a selection counter before rendering.
- Compare dates as day numbers, never as strings (a non-ISO value sorts as a string).
- Heat-grid headers need `overflow-wrap: break-word` or long tester names overflow; heat text must stay ink (white failed contrast).
- Dimming with `opacity` drops text below 4.5:1: dim bars and tints, not text.
- Tables ignore a 1px size: put a visually hidden table inside a clipping wrapper.
- Stale favicon requests show up as a console error: inline `data:,` favicon; use a fresh Chrome profile for each test run.
- Schema and fixture drift: when the exporter gains fields, update the schema and the fixtures in the same pass; validate every snapshot in the manifest, with a validator that descends into every object.
- A test expectation that hard-codes data (fixture size, people, epics) breaks when the data changes: compute it.
